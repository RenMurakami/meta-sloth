## How it got onto the board

1. `dosdcard.sh -s 32G` in `/work/flash/sloth-sd`, then `zstd -T0 -3` and `sha256sum`.
   Verified locally with `zstd -t` and `sha256sum -c`.
2. Board booted into JetPack (Ubuntu 24.04.4) from NVMe. Prechecks over SSH as
   `ren`: `/` on `/dev/nvme0n1p1`, `mmcblk0` 233G and not mounted,
   passwordless sudo.
3. `scp` of the `.img.zst` (40 s), `sha256sum -c` on the Jetson: OK.
4. `zstd -dc | sudo dd of=/dev/mmcblk0 bs=4M conv=fsync` under `nohup`:
   31.68 GB in 467 s, `WRITE-OK`. New GPT confirmed (`APP`, `APP_b` 14 GiB each).
5. Read-only mount of `mmcblk0p1` before reboot: `Sloth 0.1 (wrynose)`,
   hostname `sloth-orin-nano-sd`, `/usr/local/cuda -> cuda-13.2`.
6. `efibootmgr`: `BootOrder: 0001 (SD), 0002 (NVMe), ...` unchanged, so a plain
   reboot booted the SD.

The whole flash ran from WSL over SSH; nobody touched the board. That works
because JetPack's `ren` already holds the WSL key (`SHA256:BKe8feOA...`) and
has `NOPASSWD` sudo.

## Fixed during this run

`docs/verify/sloth-target-check.sh` used `head -1` / `head -5`. This image's
BusyBox rejects that form, so every evidence string came out empty, and the
one check that piped into `head` itself (`uvcvideo module installed`) reported
a false FAIL. Changed to `head -n N`. The first run's verdicts came from each
check's own exit status, so apart from the false FAIL they were right.

## Problems on the way, and their causes

| Symptom | Cause |
|---|---|
| 268 zero-byte RPMs in `kas-fetch/build`; `l4t-launcher` "not found" by dnf | **Windows C: was 100% full.** WSL's disk is a VHDX on C:; once C: had no room, writes inside WSL failed (457 I/O errors in `dmesg`) |
| `Invalid line '' in sstate manifest .../index-allarch` | Same: index files ended in NUL bytes from writes that never reached disk |
| Docker would not start (`read /var/run/docker.pid: input/output error`) | Same |
| `rm -rf ... died with SIGABRT` in kernel `do_package` (pseudo `path mismatch`) | Build reused a kernel work dir compiled during the disk-full crash; pseudo's ownership DB no longer matched the files |
| C: kept filling | `Temp\wsl-crashes`: the VS Code server's `node` inside WSL crashed every few minutes, each leaving a dump of up to 6.4 GB (WSL keeps 10, ~38 GB) |

Recovery: space freed on C:, WSL restarted, the four damaged build directories
deleted, fresh `build-sloth`. The shared sstate cache was checked (1127
archives written in the crash window, all pass `zstd -t`) and reused.
