Yocto 6.0 wrynose · Jetson Orin Nano Super

Sloth Yocto Image

The embedded Linux image for Sloth, a thermal-camera deer detection ECU for a Honda Civic. An InfiRay Tiny1-C camera feeds YOLOv8 running on TensorRT on a Jetson Orin Nano. This page covers what is in the image, how it is built and flashed, and what has been verified on hardware.

Sizing

The rootfs is built small (IMAGE_ROOTFS_EXTRA_SPACE = "524288", 512 MiB of slack) and grows to fill its 14 GiB partition on first boot through x-systemd.growfs. On the board it reads 13.1 G total, 8.8 G free.

  1. WSL host

    Enter the container from the top of the tree.

    Build. Use a dedicated build directory; without KAS_BUILD_DIR kas uses /work/build.

Flash

The SD card is written by the Jetson itself while it runs JetPack from the NVMe, where the SD slot appears as /dev/mmcblk0. Everything runs from WSL over SSH. Replace <ip> with the board's current address.

  1. container

    Make the whole-card image from the flash bundle.

    mkdir -p /work/flash/sloth-sd && cd /work/flash/sloth-sd
tar xf /work/build-sloth/tmp/deploy/images/sloth-orin-nano-sd/sloth-image-dev-sloth-orin-nano-sd.rootfs.tegraflash-tar.zst
./dosdcard.sh -s 32G sloth-sdcard.img
zstd -T0 -3 sloth-sdcard.img -o sloth-sdcard.img.zst
sha256sum sloth-sdcard.img.zst > sloth-sdcard.img.zst.sha256
  2. WSL host

    Switch the running Sloth system to JetPack for one boot. 0002 is the NVMe entry; the SD stays first in the boot order.

    ssh root@<ip> 'printf "\007\000\000\000\002\000" > /sys/firmware/efi/efivars/BootNext-8be4df61-93ca-11d2-aa0d-00e098032b8c && reboot'

    Fallback: HDMI and keyboard, Esc at the NVIDIA logo, Boot Manager, "UEFI Samsung SSD 990 PRO".

  3. WSL host

    Copy and verify. JetPack's ren account already trusts the WSL key and has passwordless sudo.

    cd ~/yocto/flash/sloth-sd
scp sloth-sdcard.img.zst sloth-sdcard.img.zst.sha256 ren@<ip>:~/
ssh ren@<ip> 'sha256sum -c sloth-sdcard.img.zst.sha256; findmnt -n -o SOURCE /; lsblk -d -o NAME,SIZE'

    Continue only if the checksum is OK, / is /dev/nvme0n1p1, and mmcblk0 is the ~233 G card.

  4. WSL host → JetPack

    Write the card (about 8 minutes for 31.68 GB), then reboot into it.

    ssh ren@<ip> 'zstd -dc sloth-sdcard.img.zst | sudo dd of=/dev/mmcblk0 bs=4M conv=fsync status=progress && sync && echo WRITE-OK'
ssh ren@<ip> 'sudo reboot'
  5. WSL host

    Verify. The host key changes with every new image.

    ssh-keygen -R <ip>
ssh root@<ip> 'cat > /tmp/c.sh' < ~/yocto/meta-sloth/docs/verify/sloth-target-check.sh
ssh root@<ip> sh /tmp/c.sh
The board's DHCP address has moved between .128, .129 and .130. To find it, ping the subnet and look for MAC ac:3a:e2:7c:16:35 in arp -a on Windows. A DHCP reservation on the router fixes this for good.

USB recovery-mode flashing (initrd-flash) is the only path that needs a native x86-64 Linux host. It is not used here; the SD route works from WSL.

Boot chain: QSPI firmware (owned by JetPack) → UEFI → L4TLauncher on esp → extlinux → kernel + initrd, which finds PARTLABEL=APP. UEFI boot order: 0001 SD, 0002 NVMe.

The GPT backup header sits at the 32 GB mark, not at the end of the card. Before /data can use the remaining ~200 GB, move it with sgdisk -e.

Decisions already made

  • Yocto + meta-tegra for production; JetPack stays on the NVMe for lab work.
  • JetPack owns the QSPI firmware permanently (apt-mark hold nvidia-l4t-bootloader); the Yocto side never writes it.
  • TensorRT is the only inference runtime and ONNX the interchange format. PyTorch and Ultralytics stay on JetPack.
  • OpenCV starts CPU-only; CUDA OpenCV waits for profiling data.
  • SocketCAN directly, no middleware. AUTOSAR Adaptive as design guidance only.
  • CAN-TX physically disconnected until a watchdog and safety-island design exists.
